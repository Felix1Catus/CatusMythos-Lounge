# Boundary trust gaps drive every modern exploit chain

The single strongest finding across 2024-2026 bug bounty writeups and security research is that nearly every high-impact vulnerability chain — whether in cloud infrastructure, web applications, or WAF/bot-detection evasion — shares one structural signature: **a capability granted by one component silently satisfies an unchecked trust assumption held by a second, independent component.** Researchers do not find these chains by running vulnerability scanners harder; they find them by noticing a functional oddity (a stale cache header, a redirect that "just" lands on-domain, a leftover secret in a Docker layer) outside the vulnerability class they were actively hunting, then asking "what does this let me reach that I couldn't before." The same logic recurs in WAF bypass research: the dominant 2024-2026 technique class is not signature evasion but **parser differentials** — front-end and backend components (WAF vs. app, CDN vs. origin, HTTP/1.1 vs. HTTP/2) independently implementing slightly different grammars for the same bytes, producing a gap where one side inspects nothing while the other executes everything. A 2025 academic study (WAFFLED) confirmed this is systemic, cataloguing **1,207 confirmed parsing-discrepancy bypasses** across five major commercial WAFs ([arXiv:2503.10846](https://arxiv.org/abs/2503.10846)). For a security-testing tool, the actionable consequence is that chain discovery and WAF-bypass discovery are the same kind of problem — a differential/correlation search over typed facts — not a classification problem solvable by per-finding severity scoring.

## Chains follow eleven reusable structures, not app-specific bugs

Bug bounty researchers increasingly describe their low-severity findings as reusable "gadgets" — LEGO pieces that recombine across unrelated applications rather than one-off bugs. Bugcrowd's taxonomy makes this explicit, separating *weak primitives* (open redirects, self-XSS, CSPT, cookie-tossing, Host-header trust, cache-key mismatches, schema disclosure) from the *delivery mechanisms* that weaponize them (method downgrade, CSRF, out-of-band exfiltration) ([Bugcrowd](https://www.bugcrowd.com/blog/how-to-find-bugs-on-a-hardened-target-using-gadgets/)). The clearest illustration is an SSRF filter that validates only the first-hop hostname against an allowlist and never re-checks the destination after a redirect — pairing it with an open redirect on an allowlisted host defeats the filter entirely, a pattern documented repeatedly in independent writeups and generalized in Grafana's CVE-2025-4123 ("Grafana Ghost"), where client-side path traversal plus a plugin-install open redirect chained into stored XSS, SSRF against the image-renderer, and full account takeover, with **over 36% of internet-facing instances still vulnerable mid-2025** ([SonicWall](https://www.sonicwall.com/blog/high-severity-open-redirect-vulnerability-in-grafana-leads-to-account-takeover-cve-2025-4123)). A second canonical structure is cookie scoping abuse: researchers who already held JavaScript execution on a sibling subdomain (`*.gitpod.io`) realized a subdomain-scoped, path-specific cookie write (`Domain=gitpod.io; Path=/api/authorize`) could silently override a victim's session cookie *only* during the OAuth authorize/callback flow — SameSite protections don't help because the write originates same-site — binding the victim's GitHub/Bitbucket link to the attacker's account ([Snyk Labs](https://labs.snyk.io/resources/hijacking-oauth-flows-via-cookie-tossing/)). The ChatGPT account-takeover chain ($6,500 bounty, ranked #9 in PortSwigger's 2024 top-10) shows the same logic applied to CDN/origin parser disagreement: because Cloudflare cached anything under `/share/*` by path shape without decoding `%2F..%2F`, while the origin decoded and resolved it to `/api/auth/session`, a single crafted URL caused the CDN to cache a victim's live auth token, later readable by the attacker ([nokline](https://nokline.github.io/bugbounty/2024/02/04/ChatGPT-ATO.html)). IDOR chains show the identical two-step shape in a simpler form: a first IDOR adds a victim to an attacker-controlled group (looking like a minor authz gap in a low-traffic feature), and a second IDOR or CSRF-able action — now reachable only because the victim is "inside" the attacker's group — resets the victim's password or email. Cloud and CI/CD research extends the same pattern across infrastructure trust boundaries: Varonis's GCP Dataflow chain combined a deterministic, non-secret staging-bucket name with a missing ownership check in Apache Beam's Python SDK (but not its Java SDK) and the `--save_main_session` pickling feature, letting an attacker claim a predictable bucket name ahead of a victim's job and achieve code execution the moment workers unpickled the staged session ([Varonis](https://www.varonis.com/blog/shadow-dependency-in-gcp-dataflow-cross-tenant)). A Citadelo CI/CD assessment reached production RCE purely from *defaults and absences* — a GitHub Actions bot counting toward required PR approvals, no branch protection, and a container scanner that flagged but didn't block a malicious image — demonstrating that chain-enabling primitives are frequently configuration gaps a scanner would score as "no vulnerability found" on each component individually ([Citadelo](https://citadelo.com/en/blog/cicd-security-assessment-255c8)).

## WAF bypasses cluster around framing disagreements, not signature weakness

Request smuggling research in this window, led by James Kettle/PortSwigger's "HTTP/1.1 Must Die" program, moved past classic CL.TE/TE.CL into subtler framing disagreements that specifically evade existing WAF rulesets because those rulesets are written against the old header patterns. A chunk-extension desync bug patched on Imperva's own cloud WAF exploited the fact that a bare semicolon after a chunk-size hex value (`;` with no extension name) is RFC-malformed; the front-end tolerated it and read the whole stream as one request, while the backend split a second, fully independent, uninspected request out of what it thought was still chunked body ([Imperva](https://www.imperva.com/blog/smuggling-requests-with-chunked-extensions-a-new-http-desync-trick/)). An `Expect: 100-continue`-based 0.CL variant works because WAF smuggling signatures are commonly written against obfuscated `Transfer-Encoding` headers, not `Expect` — an obfuscated value like `Expect: y 100-continue` (seen on GitLab) exposed far more vulnerable targets than the plain header and evades detection entirely ([PortSwigger](https://portswigger.net/research/http1-must-die)). This 0.CL technique, assigned CVE-2025-32094 at Akamai, was significant enough that PortSwigger built new detection methodology directly into Burp Suite Professional. A 2026 AI-assisted fuzzer, "HTTP Terminator," explored roughly 30,000 candidate desync vectors and produced a "dangling-byte" refinement that converts Response Queue Poisoning from a probabilistic, ~27,000-request race condition into a reliable two-request attack by deliberately leaving a smuggled request exactly one byte short (reported via a single secondary source pending PortSwigger's primary writeup) ([The Hacker News](https://thehackernews.com/2026/08/ai-assisted-http-terminator-finds-novel.html)). Below the smuggling layer, encoding and normalization differentials proved even more productive: the Vercel React2Shell bug-bounty challenge paid out **$170,000** across variants exploiting that a front-end WAF and the `busboy` multipart parser disagreed about which of two duplicate `boundary=` parameters, which of two duplicate `Content-Type`/charset headers, and which encoding of a malformed closing boundary marker was authoritative — in each case the WAF inspected the "wrong" half of an ambiguous grammar while busboy executed the other half ([Hacktron](https://hacktron.ai/blog/react2shell-vercel-waf-bypass)). HTTP parameter pollution showed the sharpest measured numbers: because ASP.NET and Node.js comma-join duplicate same-named query parameters before the app sees them while WAFs inspect each duplicate individually, a simple split-keyword payload bypassed **17.6%** of tested WAF configurations and a more sophisticated string-concatenation variant (splitting `alert` into `"al"+"ert"` across parameters) bypassed **70.6%** ([Ethiack](https://blog.ethiack.com/blog/bypassing-wafs-for-fun-and-js-injection-with-parameter-pollution)). Header-name mutation is the same differential applied to header parsing rather than body framing: appending characters after a space in a header name (`X-Forwarded-For abcd: z`) produces a name the front-end's strict parser doesn't recognize and passes through unmodified, while the backend's more lenient parser still binds it to the real header — this defeated an AWS API Gateway IP-allowlist and, via a control-byte variant (`X-Forwarded-For:[0x0b]z`), AWS Cognito rate limiting ([Intruder.io](https://intruder.io/research/practical-http-header-smuggling)). A distinct and recurring root cause — unconditional trust of `X-Forwarded-For` by application-level rate limiters rather than any WAF weakness — appears across multiple CVEs (Litestar CVE-2025-59152, MyTube CVE-2026-23848, 9router CVE-2026-55501) and a confirmed Acronis bounty report where header rotation defeated both login-lockout and OTP brute-force protection simultaneously ([Corgea](https://corgea.com/advisories/vulnerabilities/CVE-2025-59152), [Bugboard](https://bugboard.rsecloud.com/report/2627062)). Finally, some of the highest-impact 2024-2026 bypasses were not parser bugs at all but scope mistakes: Cloudflare's October 2025 ACME-validation-path bug let requests to a specific certificate-challenge path **completely skip all customer WAF rules**, enabling SSRF and SQLi once inspection was bypassed entirely ([SecurityAffairs](https://securityaffairs.com/187156/security/acme-flaw-in-cloudflare-allowed-attackers-to-reach-origin-servers.html)), while Zafran's "BreakingWAF" research found **more than 140,000 Fortune 1000 domains** whose true origin IP is discoverable via historical DNS or certificate SANs, meaning the WAF's protection depends entirely on origin-IP secrecy that is rarely reinforced with mutual-TLS origin pulls ([Zafran](https://www.zafran.io/resources/breaking-waf-technical-analysis)).

## AI agents introduce a new chaining substrate: scope violation plus excessive agency

The 2025-2026 window produced a genuinely new chain class specific to LLM-integrated applications, where the "boundary" being silently crossed is the trust scope between untrusted retrieved content and the privileged actions an agent is authorized to take. EchoLeak (CVE-2025-32711), a zero-click attack against Microsoft 365 Copilot, chained three bypasses in one crafted email: phrasing injected instructions as addressed to the human reader (evading the cross-prompt-injection classifier's blind spot), using reference-style markdown links to defeat the link-redaction sanitizer, and exfiltrating RAG-retrieved sensitive content via an auto-rendered image URL requiring no click — Aim Security's term for the underlying class is "LLM Scope Violation": the model processes lower-trust data (email) and lets it influence higher-trust output, with exfiltration piggybacking on an action the model was already allowed to take unmonitored ([thehackernews.com](https://thehackernews.com/2025/06/zero-click-ai-vulnerability-exposes.html)). Zenity Labs' AgentFlayer family generalizes this: the exploit value comes from *excessive agency* — an agent already holds legitimate, pre-authorized connector scopes (Drive, CRM, memory-write), and a hidden instruction in an otherwise-benign document (summarize this PDF) directs the agent to exercise those pre-existing scopes toward exfiltration, with no traditional auth bypass required ([Zenity Labs](https://labs.zenity.io/p/agentflayer-chatgpt-connectors-0click-attack)). ForcedLeak (CVSS 9.4, Salesforce Agentforce) shows the same scope-trust failure applied to infrastructure rather than data: a domain previously used by Salesforce's own systems expired, was repurchased by researchers for about $5, and — because it remained in Agentforce's "trusted domains" allowlist — let an indirect prompt injection direct the agent to exfiltrate CRM data to it, since the destination was still nominally trusted ([thehackernews.com](https://thehackernews.com/2025/09/salesforce-patches-critical-forcedleak.html)). CurXecute (CVE-2025-54135, Cursor) escalates this into persistence: an IDE agent summarizing a public Slack channel followed an injected instruction to edit its own `mcp.json` config, adding an attacker-controlled MCP server entry that runs with the developer's full OS privileges on next load — converting a read-only "summarize" task into unsandboxed command execution ([Aim Labs](https://thehackernews.com/2025/08/cursor-ai-code-editor-fixed-flaw.html)). The broader MCP ecosystem shows the same pattern at infrastructure scale: Equixly found roughly **43% of tested MCP servers had command injection flaws**, Backslash Security found hundreds bound to any-interface (0.0.0.0) exposure, and Mitiga Labs' 2026 research found malicious npm lifecycle hooks rewriting `~/.claude.json` to re-establish a malicious MCP trust relationship on every session start — surviving even credential rotation, because the payload targets the AI tool's own persisted trust state rather than the credential itself. Slopsquatting closes out this category as a supply-chain variant unique to generative coding: LLMs hallucinate plausible-but-nonexistent package names at a measured **5.2% rate for commercial models and 21.7% for open-source models** across 576,000 samples, and because hallucinations are repeatable for a given prompt, attackers can query models to discover likely hallucinated names and pre-register them with malicious payloads before a developer's coding agent installs them ([USENIX Security 2025, via Socket.dev coverage](https://socket.dev)).

## Encoding detection as capability-graph joins, not isolated signatures

Across all three domains, researchers and this corpus converge on the same encodable structure: tag every finding with the capability it *grants* and the capability it *requires* as an unmet precondition, then run a graph join — not a severity score — over the current finding set. For vulnerability chaining specifically, the concrete rule set is: (1) SSRF-filter + open-redirect — flag whenever a redirect's target domain intersects an SSRF endpoint's allowlist; (2) cookie-write + OAuth-callback-path overlap — flag any finding granting a cookie write on a domain/path overlapping an OAuth authorize/callback path's cookie-read scope; (3) cache-rule-path-prefix + edge/origin decode divergence — flag when a cache rule's matched prefix is tested against both edge and origin decoding and they diverge while a sensitive endpoint shares that prefix; (4) Host-header-reflected-into-URL + externally-readable sink — flag whenever that constructed URL is subsequently emailed, logged externally, or rendered unescaped; (5) schema-disclosure (GraphQL introspection or REST documentation) — auto-queue every enumerated resolver for an automated IDOR probe (swap the owner/ID parameter for a second test account) rather than treating disclosure as a standalone informational finding, and specifically build a "sibling-inconsistency" check that clusters resolvers by naming pattern (`set*Role`, `update*Admin`, `*Transfer`, `delete*`) and flags any cluster member that succeeds under low-privilege execution while its siblings correctly reject it; (6) method-confusion — for any delivery-blocked primitive (self-XSS, POST-only XSS), cross-check whether the same endpoint also accepts GET or a method-override parameter, and upgrade severity if so; (7) cloud/CI-CD boundary rules modeled as explicit boolean co-occurrence checks, e.g. `approvers_include_non_human_identity == true AND branch_protection_required_reviews == 0 AND deploy_gate_blocks_on_scan_result == false` fires only when all three co-occur on the same repo-to-deploy path, since any single condition alone is only a medium finding. For WAF bypass detection, the equivalent encoding is differential testing rather than graph joins: send the same logical request through N syntactically-legal-but-ambiguous variants (duplicate `boundary=` parameters, duplicate charset headers, obfuscated `Expect`/`Transfer-Encoding`, duplicate same-named query parameters, header names with trailing junk) and diff the WAF's block/pass decision against the backend's actual parsed behavior — any divergence is an automatic candidate finding requiring no manual signature knowledge. The nowafpls technique generalizes to a cheap binary-search test: send a known-blocked payload at byte offset 0, then resend with increasing benign padding before it, to locate the WAF's inspection byte limit. For AI-agent-specific chains, the automatable pattern is a connector/scope audit plus canary injection: enumerate every tool/connector scope an agent holds, craft a minimal hidden instruction targeting exactly that scope toward a canary resource, inject it via the agent's normal untrusted-ingestion channel, trigger the benign task a real user would run, and assert the canary action never fires — any successful canary firing is a scope-violation finding regardless of which specific classifier or sanitizer it evaded.

## Conclusion

The research converges on a single implementation mandate: a security-testing tool that wants to find these chains needs a **typed fact store with trust-boundary tags on every primitive** (tenant, pipeline stage, agent connector scope, cache layer, WAF-vs-origin parse state) and a small library of cross-boundary join and differential rules, rather than a better single-finding classifier or a richer signature database. The most concretely automatable rules found — sibling-mutation authorization inconsistency, Docker layer-diff secret recovery, and WAF-vs-backend parse differential testing — are all *relational*, comparing a finding against its siblings, its history, or a second component's interpretation of the same bytes, rather than matching a single-point signature. The AI-agent chaining class (EchoLeak, AgentFlayer, CurXecute, ForcedLeak) is the newest instance of the same underlying logic applied to a new trust boundary — the line between untrusted retrieved content and an agent's pre-authorized tool scope — which suggests that as agentic systems proliferate, "scope violation" will become as foundational a chaining primitive as "missing ownership check" or "parser differential" are today, and testing tools built only around HTTP-layer or cloud-IAM boundaries will miss it entirely unless they add connector-scope and tool-description auditing as a first-class fact type.
